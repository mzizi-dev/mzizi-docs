<Note>
  This is the CLI for working with Mzizi's **components and doctrine** in a project. It is one Rust
  binary, `mz`, which also carries the language's own commands (`mz check`, `mz build`, `mz run`;
  see [the compiler](/compiler)). The registry and agent commands below live next to them. The
  source is [mzizi-dev/mzizi-cli](https://github.com/mzizi-dev/mzizi-cli).
</Note>

The CLI is **free, with no gate**. That is the owner's decision of 29 September 2026: gating
starts only at Fundi, which ties into the console.

## Install

Pick one route. They all give you the same `mz`. The latest published version is `0.14.1`,
checked on npm and crates.io on 23 November 2026.

```bash
npx @nyuchi/mzizi-cli add button     # npm, one shot (Node 18 or later)
npm i -g @nyuchi/mzizi-cli           # npm, global; then: mz --help
cargo install mzizi-cli --locked     # from crates.io; installs mz
```

The npm package [`@nyuchi/mzizi-cli`](https://www.npmjs.com/package/@nyuchi/mzizi-cli) is a
small launcher with the binary for your platform inside it (macOS on arm64 and x64, Linux on
arm64 and x64 with glibc or musl, Windows on x64). It has no CLI logic of its own.
`mzizi` and `fundi`, the names of the old TypeScript CLI, still work and print a deprecation
note; use `mz`.

<Warning>
  **Use `0.14.1` or later, not `0.14.0`.** The `0.14.0` npm package shipped its binaries without the
  execute bit, so `mz` failed with `EACCES` after `npm install`. `0.14.1` fixes it, and `cargo
  install` was never affected.
</Warning>

What changed in the Rust CLI, and before it:

| Version  | Change                                                                                                                                                                                                                                          |
| -------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `0.14.1` | The npm launcher repairs a binary that lost its execute bit; the release is smoke-tested from npm and crates.io                                                                                                                                 |
| `0.14.0` | The CLI is a Rust binary, `mz`, ported from the TypeScript CLI with no behaviour change except the names. `mzizi check` is `mz floor`, because `mz check` belongs to the language compiler. The floor thresholds are read from the Mzizi tokens |
| `0.13.0` | The last TypeScript release                                                                                                                                                                                                                     |
| `0.9.0`  | `add` takes `--type` and installs five types: `mzizi`, `tsx`, `astro`, `swift` and `kotlin`, with `rust` and `typescript` accepted as spellings of `mzizi` and `tsx`                                                                            |
| `0.8.0`  | Adds the spacing check, now `mz floor` (see [the spacing layers](/foundations/spacing-layers))                                                                                                                                                  |
| `0.7.0`  | Adds `--target astro`, and infers it in an Astro project                                                                                                                                                                                        |

## Commands

| Command                          | What it does                                                                                                                                                             |
| -------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `mz add <name...>`               | Installs components from the registry, with their dependencies. Rust first. No API key and no sign-in                                                                    |
| `mz floor [path...]`             | Checks your source against [the spacing layers](/foundations/spacing-layers): exit code 1 on a violation. `--json` for a report. Was `mzizi check`                       |
| `mz explore`                     | Reads a few files (`package.json`, `tsconfig.json`, the global stylesheet, the Tailwind config, `components.json`) and prints a project snapshot. Offline. No model call |
| `mz plan <goal>`                 | **Read-only.** Plans the minimal edits to wire Mzizi in, and prints them as a dry run                                                                                    |
| `mz chat <message>`              | One-shot chat scoped to Mzizi doctrine                                                                                                                                   |
| `mz login` / `logout` / `whoami` | Save, clear or show a console token (kept in the OS keychain when there is one). Only the sign-in operations need one                                                    |

<Note>
  **`mz floor [path...]`.** It fails with exit code 1 on padding, gaps, negative margins and line
  heights under [the spacing layers](/foundations/spacing-layers), and takes `--json`. Its
  thresholds are read from the Mzizi tokens, not typed into the tool. Under the old names (`mzizi`,
  `fundi`) the command is still spelled `check`.
</Note>

## `mz add`: the registry installer

```bash
mz add button --type mzizi      # Mzizi (Rust only), explicitly
mz add button --type tsx        # the TypeScript (React) build
mz add app-data-table --type astro  # the pure Astro build, into src/components/mzizi/
mz add mzizi-tokens-swift       # native: the only type it has, so no flag
mz add button                   # infer the type from the project
mz add address-input --dry-run  # print the plan, write nothing
mz add card --overwrite         # replace files that already exist
```

It resolves a component and its registry dependencies from `api.mzizi.dev` and needs no
account and no API key. It does not touch the MCP server.

**Rust first.** For a Rust project, `mz add` does not copy `.rs` sources in. It names the
crate that holds the component and prints the `cargo add` to run, because the crates are on
crates.io (see [Mzizi Roots](/roots/overview#install)). In a project with only a
`Cargo.toml`:

```text
$ mz add button
button: type mzizi (Cargo.toml present and no package.json); available: …
…
crate dependency: mzizi-ui (crates.io)

Still to do — add the crate dependency:
  cargo add mzizi-ui
```

The crate name comes from the `crate` field of the API's `/v1/rs/{name}` response, which
names each component's own crate: `mz add mzizi-alert-banner` records `mzizi-brand`, and
`mz add mzizi-footer` records `mzizi-shell`.
[The Roots crate list](/roots/overview#what-exists-today) says what each crate holds, and
`mzizi-roots` brings the UI crates in one dependency.

For a React project, it writes the `.tsx` files and lists the npm packages they need, as the
shadcn CLI would.

**The type** is chosen per component, Mzizi first, TypeScript second, native after (owner,
4 November 2026). `mzizi` means Rust only: it never emits Astro or TypeScript, which are
separate implementations served from their own files. From `0.9.0` the types are:

| Type     | Served from                                 | What it installs                                     |
| -------- | ------------------------------------------- | ---------------------------------------------------- |
| `mzizi`  | `/v1/rs/<name>` (Mzizi Roots, Rust only)    | a crate dependency, not a file copy                  |
| `tsx`    | `/v1/ui/<name>`                             | the TypeScript (React) files                         |
| `astro`  | `/v1/astro/<name>`                          | pure `.astro` into `src/components/mzizi/`           |
| `swift`  | `/v1/ui/<name>`, `.swift` files it declares | the Swift files (for example `mzizi-tokens-swift`)   |
| `kotlin` | `/v1/ui/<name>`, `.kt` files it declares    | the Kotlin files (for example `mzizi-tokens-kotlin`) |

`--type` wins when given, and a type the component lacks is refused, naming the types it has.
Otherwise the project's own files decide: `Cargo.toml` alone is `mzizi`; `components.json`,
or `react` or `next` in `package.json`, is `tsx`; `astro.config.*` or `astro` in the
dependencies is `astro` (even with React islands); `Package.swift` is `swift`; a Gradle build file
is `kotlin`. If the project has none of these, `mz add` takes the only type the component has,
and otherwise refuses and asks for `--type` rather than guess. A project with both a `Cargo.toml`
and a `package.json` is ambiguous, so it refuses too.

The Astro build (from `0.7.0`) installs a component's pure `.astro` from
`api.mzizi.dev/v1/astro/<name>`, with every registry file it imports and any brand asset, into
`src/components/mzizi/`, and refuses by name a component that has no `.astro` rather than
install its `.tsx`.

## Model access

`ANTHROPIC_API_KEY` is optional. Like `tsc`, the CLI is usually run by a coding agent that
already has model access. Without a key, `plan` prints a deterministic context bundle, the
project snapshot plus the Mzizi skills that match your goal, for that agent to plan from, and
`chat` points you back at the agent. With a key, `plan` and `chat` run Fundi's own agent loop.

## Registry access

`plan` and `chat` read the registry through [the MCP server](/toolchain/mcp), which serves
every operation but the sign-in ones without sign-in. So `explore`, `plan`, `chat` and `add` need no
account. `mz login` exists only for the sign-in operations, which act as a Mzizi console user.

## Safety

- **Planning is read-only.** Writing a file and running a shell command are blocked while
  planning, and reachable only through an explicit non-dry-run apply.
- **Everything is sandboxed to the project root.** A path that escapes it, or that goes through a
  symlink, is rejected, in planning, in apply and in `mz add`. Registry documents may only name
  files on `api.mzizi.dev`.
- **`mz add` does not overwrite by default.** A file that already exists is not replaced unless you
  pass `--overwrite`.
- **The CLI never holds a machine credential.** It reaches Fundi only through the MCP server,
  which acts for a signed-in user.

## Not a library any more

The TypeScript CLI (up to `0.13.0`) also exported `createFundi()`. The Rust CLI is a program, not a
library, and the npm package no longer exports it. Use the commands above, or the
[MCP server](/toolchain/mcp), which serves the same registry and doctrine to any agent.
