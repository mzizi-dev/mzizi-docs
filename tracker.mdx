<Warning>
  **Mzizi is not yet a working programming language.** Mzizi has no modules or standard
  library yet, and its text operations are partial. A [`program`](/programs) has expressions,
  bindings, functions, control flow, numbers, results, lists, maps, sets and records with
  methods, in a narrow form. C1–C5 and C7–C10 are ✅ in the file as of the third release of
  8 October 2026 (`4d0cdc3`, no tag yet when checked); C6 is 🟡. A `service` lowers to a local
  Rust + axum package and a program to a dependency-free Rust package; no component lowers, and
  there is no Workers, Containers or WebAssembly target.
</Warning>

[`LANGUAGE-TRACKER.md`](https://github.com/mzizi-dev/mzizi/blob/main/LANGUAGE-TRACKER.md), at
the root of `mzizi-dev/mzizi`, is the one list of what Mzizi still needs before it can be
called a working programming language, stacked against the languages it aims to replace. By
the owner's decision of 30 September 2026 it is the ultimate tracker: **if a capability is not
✅ there, Mzizi does not have it, whatever any other page says.** These docs take every
capability claim from it. This page summarises it at language `main` `4d0cdc3` (the third release of 8 October 2026);
read the file for the evidence behind each row.

Status in the tracker is what the code on `main` does, never what an RFC designs:

| Mark | Meaning                                                             |
| ---- | ------------------------------------------------------------------- |
| ✅   | On `main`, tested in CI                                             |
| 🟡   | Partly there: a narrow form exists, or it exists in an open PR only |
| 📝   | Designed in an RFC, not implemented                                 |
| ❌   | Neither designed nor implemented                                    |

## Where Mzizi stands today

What exists is the front end of a language whose first domain is UI components:

- **Syntax:** 23 keywords (`compiler/src/lex.rs`), one component per file.
- **Types:** `bool`, `int`, `text`, enums with data columns, records, `list(T)`, `option(T)`
  and `event(T)` ([RFC-0008](/rfcs)).
- **Toolchain:** `mz check` (with `--agent`), `mz fix`, `mz contract`, `mz outline`,
  `mz build`, `mz run` and `mz harness`; a recovering parser (blocks nest at most 64 deep, past
  which one `MZ0411`), a resolver and a content-addressed IR. See [the compiler](/compiler).
- **Written in Mzizi:** nine [primitives](/primitives), two component examples and one
  service, `examples/registry.mz`.
- **The backend slice** ([RFC-0011](/rfcs), language PRs #29–#33): a
  `service` with HTTP routes and handlers, checked by `mz check`, run in process by
  `mz contract`, and lowered by `mz build` to a local Rust + axum package, which CI compiles,
  tests and serves. The `mzizi-be` benchmark arm, the probe crate `mzprobe` and backend task
  B1 exist; no backend episode has run.

**The core language, in a `program`** ([RFC-0013](/rfcs), released to `main` on 8 October
2026): `fn main`, functions with typed parameters and recursion, `let`, `var` and assignment,
`int`, `float`, `bool` and `text` with the numeric methods and the text methods, `when` / `else
when`, `match`, `for each` over a list or `range`, `while`, `break`, `continue`, enums with
columns, `list`, `map` and `set` with their methods, records with methods and `always`
invariants, `result(T, E)` with `error` and `try`, and `print`. `mz run` lowers it to a
dependency-free Rust package, builds it and runs it, and CI runs eight example programs against
their committed output. See [Programs](/programs).

The tracker marks C1–C5 and C7–C10 ✅ as of the third release, and C6 is 🟡: its methods are on
`main`, but the ones that return an option or a list are not built, and the row waits on the
standard library (P2). P4 and H1 stay 🟡: a general program cannot be written yet, and the
plugin host and the generated skills are not built.

What does not exist yet: the text methods that return an option or a list, `option(T)` written
as a type, methods that change their record, generics, modules, a standard library, lowering for
a component, and most of Tier 2 and Tier 3.

## Against the languages Mzizi aims to replace

Mzizi's column from the tracker, condensed. The tracker also gives each incumbent's answer
(Python, Go, C++, TypeScript and Rust have every one of the first rows).

| Area                                     | Mzizi today                                                                                                                                        |
| ---------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------- |
| Expressions, variables, functions, loops | 🟡 in a `program`: expressions, `let` / `var`, functions and recursion, `when`, `match`, `for each` over a list or a range, and `while`; no tuples |
| Numbers                                  | 🟡 `int` and `float` in a `program`; no decimal                                                                                                    |
| Text operations                          | 🟡 in a `program`: length, search, `trim`, case, `replace`, `repeat`; no slicing, splitting or parsing                                             |
| Collections                              | ✅ in a `program` (C7): `list`, `option`, `map` and `set`, with their methods and folds; no tuples                                                 |
| User types                               | 🟡 enums with data, records with methods and `always` invariants; no methods that change their record, payload enums, traits or generics           |
| Error handling                           | 🟡 in a `program`: `result(T, E)`, `return error(e)`, `try`, `match` on a result; contracts check behaviour, they are not error handling           |
| Modules and imports                      | ❌ (one component per file)                                                                                                                        |
| Standard library                         | ❌                                                                                                                                                 |
| Concurrency                              | ❌                                                                                                                                                 |
| Compiles to something that runs          | 🟡 a `service` → a local Rust + axum package; a `program` → a dependency-free Rust package that `mz run` builds and runs; no component lowers      |
| Uses the host ecosystem                  | ❌ (no Rust crate interop)                                                                                                                         |
| Package manager                          | ❌                                                                                                                                                 |
| Formatter, editor support                | ❌ (canonical form designed in RFC-0001)                                                                                                           |
| Tests                                    | 🟡 `mz contract` for contracts; no `mz test`                                                                                                       |
| Diagnostics built for agents             | ✅ `mz check --agent`, `mz fix`                                                                                                                    |
| Contracts on everything                  | ✅ components; 🟡 services, run in process by `mz contract`, `ensure` tested over generated requests, not proven                                   |
| Spec and stability                       | ❌ (the RFCs are design, not a reference)                                                                                                          |

The two ✅ rows are where Mzizi is different on purpose. Every other row is work.

on `main` and green.

[The language harness](/language-harness) (H1) is the spine of the language, what the agent
reads. The agent protocol (`mz check --agent`, `mz fix`) and a first slice of entries exist:
`compiler/src/harness.rs` registers every program feature and its codes, and `mz harness`
prints them. The plugin host and the generated skills are design only
([RFC-0012](/rfcs), a draft).

## What each step unlocks for the benchmark

Phase 0's goal cannot be tested beyond what the language can express
([the benchmark](/benchmark)):

| Task family                                                                | Needs                 | Status                                                                                                                                                                                |
| -------------------------------------------------------------------------- | --------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| UI components against Dioxus, Leptos and React                             | What exists today     | Runnable now. Two pilots on 2026-09-27, against Dioxus only, showed no advantage                                                                                                      |
| Backend handlers (B1 routing) against TypeScript, Python, Go, C++ and Rust | A `service`           | Not yet runnable: the runner does not score an episode with probes, and B2–B5 and the other-language arms do not exist. Nothing measured                                              |
| Public suites (MultiPL-E, EvalPlus)                                        | C1–C10 and part of P2 | **Blocked: functions, floats, loops, `match`, results, collections and records run in a `program`; the text operations are partial (C6), and the standard library (P2) is not built** |
| Aider polyglot, BaxBench                                                   | Tier 1, P1, P2, P8    | Blocked                                                                                                                                                                               |
| Runtime performance against hand-written Rust (`benchmarks/perf/`)         | A `program` (C10, P4) | **Runnable; CI gates output agreement only.** Timings are per machine, not committed, and never a claim                                                                               |

The kill-criterion run has not happened. Nothing in the tracker is a claim that Mzizi is
better than any language; it lists what has to exist before that can be measured.

## Toward M1

Work toward M1 is tracked in [mzizi#69](https://github.com/mzizi-dev/mzizi/issues/69). Its
design, RFC-0013, and its Wave 0 and part of Wave 1 (C1, C4, C5, C9, with C2, C3 and C10 from
Wave 0) were released to `main` on 8 October 2026 (mzizi#91, tagged `v0.5.0`). The second
release of that day (mzizi#96, tagged `v0.6.0`) moved their rows to ✅ in the file. The third
release (mzizi#104) carried collections (C7, mzizi#99), records with methods (C8, mzizi#101 and
mzizi#102) and text methods (C6, mzizi#98), and made C7 and C8 ✅. C6 stays 🟡, so M1 is not
reached. Still to build: the text methods that return an option or a list, which C7's options
now make possible, the standard library (P2) that C6 waits on, and the follow-ups the RFC lists.
See [Status](/status#released-to-main-on-8-october-2026) and [the M1 plan](/roadmap#m1-the-plan).
