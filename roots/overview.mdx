**Mzizi Roots** is the name for Mzizi's own branded components rebuilt in Rust: **UI and
server components, built for the agentic web.** It is where new component work goes.

## Rust first

- **Rust is the lead.** Where a Rust implementation of a component exists, it is the one to
  use, and these docs present it first.
- **The React build keeps working.** The React and TypeScript (`.tsx`) components stay in
  the registry and stay installable. They are **deprioritised**: not the lead, and not where
  new work goes. These docs call them **the React build**.
- **UI and server.** Roots covers the handlers that serve a component as well as the
  component, which is the charter's full-stack shape for Phase 1.

This follows from the owner's direction for Mzizi as a whole: the frontend is either Astro
with Mzizi UI (Roots) underneath, or pure Rust end to end, and everything built carries a
contract. See [the roadmap](/roadmap).

## How Roots relates to the language

Roots components are written in Rust today, not in Mzizi. The language cannot produce them
yet: no component lowers to Rust (a `service` does, to a local axum package, and a `program`, to a
dependency-free Rust package), and Phase 1
waits on the benchmark ([Status](/status)).

Roots is built to support the language: it is meant to be the language's component model,
the way React is JavaScript's, with Rust as the platform underneath. When the language
lowers components to Rust, Roots is its target: the RFC writes every Roots contract in the language's
`contract … end` grammar. That is a design intention, gated on the benchmark like the rest
of Phase 1.

Until then, the components also do a second job. The registry's components, React and Rust
together, are the ground truth for the benchmark's UI tasks. The nine
[primitives](/primitives) are hand ports of registry components, and the benchmark scores a
candidate against a component's Rust reference. That is one of the components' jobs, not
what they are, and not the benchmark's goal, which is Mzizi against the best existing
language for each kind of task ([the benchmark](/benchmark)).

## What exists today

The Rust half of the registry lives in `mzizi-rs/` in
[`mzizi-dev/mzizi-registry`](https://github.com/mzizi-dev/mzizi-registry), a Cargo workspace.
All fourteen of its crates are on crates.io at `0.11.0` (checked 23 November 2026): eight node
crates, one per node that has Rust, two umbrella crates that re-export them, and four
supporting crates (`mzizi-harness`, `mzizi-data`, `mzizi-mongodb` and `mzizi-activitypub`). The
crates move together. `0.1.0` was the first release (29 September 2026); `0.2.0` and `0.3.0` were
published on 7 October 2026, `0.4.0` on 20 October for registry release v4.9.0, `0.5.0` with
registry release v4.16.0, `0.6.0` with v4.17.0 (published 25 October 2026) `0.7.0` on 1 November 2026, and `0.8.0` on 17 November 2026. The `0.8.0` release carried the work in registry release 4.42.0; registry release 4.43.0 fixed crate publishing. `0.4.0` was
**breaking** for code that builds or matches `Inline::Link` (links now carry a `title`) or
`ListItem::children` (now `Vec<ListChild>`), and `0.5.0` was **breaking** for `mzizi-mongodb`,
which refuses cross-collection `$lookup`, `$graphLookup` and `$unionWith` in `aggregate` (use
`aggregate_joining`) and returns `Zeroizing` wrappers from `Uri::password` and
`scram::salted_password`. The registry's changelog has each release in full.

**The render path.** The components are Mzizi's own, not borrowed from another framework. Their
render path is moving to Mzizi's own `render(props) -> String`: registry
[#506](https://github.com/mzizi-dev/mzizi-registry/pull/506) and
[#510](https://github.com/mzizi-dev/mzizi-registry/pull/510) are merged, with a skeleton and six
static primitives. **Dioxus is out of the stack (owner, 4 November 2026).** Its removal is in progress, not
finished. The core of `mzizi-roots` no longer depends on Dioxus (`0.8.0`). Eight components render
unstyled from `mzizi-roots`: alert, badge, card, chart, markdown-renderer, progress,
safe-area-frame and separator. Removing Dioxus from the remaining components is ongoing, and
more steps follow. The removal is tracked in
[`mzizi-registry#635`](https://github.com/mzizi-dev/mzizi-registry/issues/635).

## The unstyled pattern

Components carry structure, state and ARIA, and no styling. They expose `data-slot`,
`data-variant`, `data-size` and `data-state` hooks, so a team styles them with its own CSS.
`tokens.css` holds values only, `floor.css` the accessibility minimums, and `mzizi-theme.css`
is an opt-in look. The button is the first pattern component, in React, Astro and Rust. Its
stylesheets are built with Lightning CSS by the `mzizi-css` tool. Moving the other components
to this pattern is the direction and is in progress, so Tailwind is not yet removed from them.

Because the structure and the floors are separate from any brand, any team can adopt Mzizi's
components and accessibility floors without taking on the Nyuchi or Mukoko brand.

## Install

```bash
cargo add mzizi-roots            # the UI side: tokens, primitives, brand and shell
cargo add mzizi-roots-server     # the server side: assurance, fundi, docs and discovery
```

Each umbrella turns every feature on by default. `mzizi-roots` has the features `ui`, `brand`
and `shell`, and always includes `mzizi-tokens`. `mzizi-roots-server` has `assurance`,
`fundi`, `docs` and `discovery`; `docs` brings in the UI dependency that is being removed, because `mzizi-docs` also carries
two documentation renderers. To take less, turn the defaults off and name what you need, or
depend on a single node crate:

```bash
cargo add mzizi-roots --no-default-features --features brand
cargo add mzizi-brand
```

The node crates are the ones that compile each component, and they keep their names.

`cargo add` takes the newest release, `0.11.0`. To write the dependency by hand, use the
requirement the crate READMEs use:

```toml
[dependencies]
mzizi-roots = "0.11"
```

To turn the defaults off on the same line, write `mzizi-roots = { version = "0.11", default-features = false }`.

## The first batch: twelve brand components

The first Roots batch converts twelve N3 brand components, where there was no Rust at all
before: `mzizi-alert-banner`, `mzizi-avatar-stack`, `mzizi-cover-header`, `mzizi-empty-state`,
`mzizi-escalation-card`, `mzizi-gauge-card`, `mzizi-hero-stat`, `mzizi-meta-tile`,
`mzizi-stats-row`, `mzizi-success-screen`, `mzizi-suitability-card` and `mzizi-user-card`.
They ship in `mzizi-brand`.

**Each one carries a contract, checked against its rendered output.** The contract has two
parts. The registry contract is the one every component has: one name, one set of variants,
the same `data-slot`, `data-portal` and tokens as the React build, asserted against the
`.tsx` sibling. On top of that, each module exports clauses in the language's
`contract … end` grammar, three to eight per component and 65 in all. The crate's contract
suite renders each component and evaluates every clause against the markup
it emits. A clause it cannot evaluate fails. For example, from `mzizi-alert-banner`:

```text
contract
  slot is "mzizi-alert-banner"
  portal is "https://mzizi.dev/components/mzizi-alert-banner"
  role is "alert"
  every alert_severity label not_empty
  watch.mineral uses "--severity-cold"
  button "Dismiss" min_height 48
  button "View Details" min_height 48
end
```

These clauses are evaluated by Rust tests in the registry, not by `mz contract`. The
language's own evaluator checks a `.mz` component against itself and cannot read Rust.

The ports also fix six defects the React build still has, such as a 40px button under the
45px touch floor and an unclamped `aria-valuenow`. Each fix has a test.

## The Markdown renderer

From `0.8.0` the renderer is in `mzizi-roots`, at `mzizi_roots::components::markdown_renderer`. `mzizi-ui` carried it through `0.7.0`, and no longer exports it ([registry #710](https://github.com/mzizi-dev/mzizi-registry/issues/710)).

It shows Markdown, including text written by other people, **safe by construction**. It parses the text into a typed tree of blocks and inlines, and renders only that tree. Raw HTML in the source shows as written.

The props are `RenderProps`: `content`, `links` (`MarkdownLinks`), `from` (`MarkdownSource`), `heading_base` and `class`. `render` returns the markup as a `String`:

```rust
use mzizi_roots::components::markdown_renderer::{render, MarkdownLinks, RenderProps};

let markup = render(&RenderProps {
    content: "**Hi** [docs](https://mzizi.dev)".to_string(),
    links: MarkdownLinks::Https,
    ..Default::default()
});
```

- **Raw HTML is text.** `<script>`, `<img onerror>` and `<a href>` in the source show as written.
- **Links pass an allow-list.** By default (`MarkdownLinks::Safe`) http, https, mailto, tel and
  relative addresses are kept; `MarkdownLinks::Https` keeps https only. From `0.3.0`, an address
  with whitespace or a control character inside is refused, and a web address needs a host and no
  credentials, so `https://bank.example@evil.example` is refused. A refused link keeps its words
  and loses its address. http and https links open in a new tab with `rel="noopener noreferrer"`.
- **Rich text.** `from: MarkdownSource::Html` (or `Auto`) reads an editor's HTML into the same
  tree with a small reader that builds plain data, never a DOM. From `0.3.0` a nested list stays
  nested and `<ol start>` keeps its first number.
- **`heading_base`** shifts `#` headings under a page's own headings.
- **Hostile text stays linear.** Each inline parse has a scanning budget, and nesting is bounded.

The Rust build is one of three under one contract,
[`contracts/ui/markdown-renderer`](https://github.com/mzizi-dev/mzizi-registry/blob/main/contracts/ui/markdown-renderer.contract.json)
(1.1.0): the React build and a pure Astro build are held to the same states, including a hostile
one, and the TypeScript and Rust suites run the same 55 shared cases. The Astro build installs
from the registry (`mzizi add markdown-renderer --target astro`); the contract names
`@bundu/ui/MarkdownRenderer.astro` from `@bundu/ui` 0.6.0, which is not on npm yet (`0.5.0` was
the latest on 7 October 2026). The Rust source is at [`/v1/rs/markdown-renderer`](https://api.mzizi.dev/v1/rs/markdown-renderer). When it was checked on 17 November 2026 it still named `mzizi-ui` as the crate, while the 0.8.0 source has the renderer in `mzizi-roots`. `api.mzizi.dev` serves the safe React and Astro builds too.

## Reading the Rust source

You can read a component's Rust source over the API:

```bash
curl https://api.mzizi.dev/v1/rs/button
```

That route is a read surface, not an install path: depend on the crate instead. Each
document's `crate` field names the crate its component ships in, so it answers which one to
depend on:

```bash
curl -s https://api.mzizi.dev/v1/rs/mzizi-alert-banner | jq .crate
# { "name": "mzizi-brand", "registry": "crates.io", "git": "https://github.com/mzizi-dev/mzizi-registry" }
```

From registry commit `9b86e03` on, `/v1/rs/{name}` serves all twelve brand components, each
naming `mzizi-brand`, alongside the primitives in `mzizi-ui`, the app chrome in `mzizi-shell`
and the server rungs in their own crates. On 30 September 2026 the API was built from that
commit, and so was the [MCP server](/toolchain/mcp). Both pins move, so read the live one from
the source: the API's `x-mzizi-source` header, or the MCP server's `catalogue.json`.

The MCP server is Rust first too: the `get_component` operation leads with the component's crate,
its `cargo add` line, its contract and its `.rs` source, then gives the pure Astro build where
there is one (from `mzizi-mcp` `0.12.0`), and the React build last.
